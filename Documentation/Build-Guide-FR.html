Avant de commencer

La plupart des utilisateurs n'ont pas besoin de ce guide : des fichiers prêts à l'emploi sont disponibles sur la page Releases du projet. Compilez BATC Remote vous-même si vous voulez vérifier exactement ce que vous lancez, essayer les dernières modifications, ou modifier l'app.

À la fin de ce guide, vous aurez dans un dossier nommé dist :

  • BatcRemote.exe, le petit programme Windows qui sert l'app à votre téléphone ;
  • BatcRemote-debug.apk, l'app Android (seulement si vous installez Android Studio, voir plus bas).

Ce qu'il vous faut :

  • un PC sous Windows 10 ou 11 (64 bits) ;
  • une connexion Internet (les outils et la première compilation téléchargent plusieurs centaines de mégaoctets) ;
  • de l'espace disque libre : environ 2 Go pour le programme Windows seul, et environ 10 Go de plus pour l'app Android ;
  • un compte qui a le droit d'installer des logiciels sur le PC.
Comment lire ce guide

Les commandes sont présentées dans des cadres sombres. Cliquez sur Copier, puis collez-les dans PowerShell avec un clic droit (ou Ctrl+V) et appuyez sur Entrée. Les lignes qui commencent par # sont des commentaires : elles sont ignorées.

Ouvrir PowerShell

PowerShell est la fenêtre de Windows dans laquelle on tape des commandes. Il est déjà installé.

  1. Cliquez sur le bouton Démarrer (ou appuyez sur la touche ⊞ Win).
  2. Tapez PowerShell.
  3. Cliquez sur Windows PowerShell (ou Terminal). Une fenêtre avec un curseur clignotant s'ouvre.

Inutile de le lancer en tant qu'administrateur : les programmes d'installation demanderont eux-mêmes l'autorisation quand c'est nécessaire.

BATC Remote se compile avec quatre outils gratuits. Le tableau indique ceux dont vous avez besoin.

Solution 1 (la plus simple) : installer avec winget

winget est le gestionnaire d'installation intégré à Windows 10 et 11. Copiez ces commandes dans PowerShell. Chacune télécharge et installe un outil ; acceptez les demandes de Windows (« Voulez-vous autoriser cette application à apporter des modifications à votre appareil ? ») quand elles apparaissent.

# Obligatoires
winget install -e --id Git.Git
winget install -e --id OpenJS.NodeJS.LTS
winget install -e --id Microsoft.DotNet.SDK.8

# Seulement si vous voulez l'app Android
winget install -e --id Google.AndroidStudio

La première fois, winget peut vous demander d'accepter les conditions de ses sources : tapez Y puis appuyez sur Entrée.

Solution 2 : installer depuis les sites officiels

Si winget n'est pas disponible, téléchargez chaque programme d'installation et lancez-le en gardant les options par défaut :

  • Git : git-scm.com/download/win
  • Node.js : nodejs.org — choisissez la version LTS
  • SDK .NET 8 : dotnet.microsoft.com/download/dotnet/8.0 — choisissez SDK, Windows x64
  • Android Studio : developer.android.com/studio
Important : fermez puis rouvrez PowerShell

Une fois tout installé, fermez la fenêtre PowerShell et ouvrez-en une nouvelle (étape 1). Une fenêtre déjà ouverte ne voit pas les outils qui viennent d'être installés.

Préparer Android Studio

Passez cette étape si vous ne voulez pas l'app Android. Android Studio doit être ouvert une première fois pour qu'il télécharge le SDK Android. Son interface est en anglais.

  1. Ouvrez Android Studio depuis le menu Démarrer.
  2. S'il propose d'importer des réglages, choisissez Do not import settings.
  3. Dans l'assistant de configuration, cliquez sur Next, choisissez le type d'installation Standard, puis Next.
  4. Sur l'écran des licences, sélectionnez chaque licence à gauche et cliquez sur Accept, puis sur Finish.
  5. Attendez la fin des téléchargements (cela peut prendre un moment), puis fermez Android Studio. Inutile de créer ou d'ouvrir un projet.

Gardez les emplacements par défaut : le script de compilation trouve tout seul le SDK Android dans %LOCALAPPDATA%\Android\Sdk et Java dans le dossier d'Android Studio.

Vérifier les outils

Dans une nouvelle fenêtre PowerShell, lancez :

git --version
node --version
npm --version
dotnet --list-sdks

Vous devez voir quelque chose comme ceci (vos numéros peuvent être plus élevés) :

git version 2.51.0.windows.1 v24.19.0 11.6.0 8.0.425 [C:\Program Files\dotnet\sdk]
  • node doit afficher v22 ou plus.
  • dotnet --list-sdks doit lister au moins un SDK qui commence par 8. ou plus.

Si l'un d'eux répond « n'est pas reconnu en tant que nom d'applet de commande », voir Dépannage.

Télécharger le code source

Nous allons placer le code dans C:\Dev\BATC-Remote. Un chemin court et sans espace évite des problèmes, et mieux vaut rester en dehors des dossiers synchronisés par OneDrive.

mkdir C:\Dev -Force
cd C:\Dev
git clone https://github.com/Proxi64/BATC-Remote.git
cd BATC-Remote

La dernière commande place PowerShell dans le dossier du projet. La ligne de commande se termine maintenant par C:\Dev\BATC-Remote>.

Sans Git

Sur la page GitHub, cliquez sur le bouton vert Code, puis sur Download ZIP. Décompressez le ZIP dans C:\Dev et renommez le dossier obtenu en BATC-Remote. Puis, dans PowerShell : cd C:\Dev\BATC-Remote. Vous ne pourrez pas utiliser git pull plus tard (étape 9) : il faudra retélécharger le ZIP.

Compiler

Tout est fait par un seul script, build.ps1, à la racine du projet. Lancez-le depuis le dossier du projet :

powershell -ExecutionPolicy Bypass -File .\build.ps1

-ExecutionPolicy Bypass autorise Windows à lancer ce script une fois, sans modifier aucun réglage de sécurité de votre PC.

Le script enchaîne ces étapes ; les titres en couleur indiquent où il en est :

  1. Web app : télécharge les bibliothèques nécessaires, vérifie le code, lance les 63 tests automatiques, puis compile l'app. Vous devez voir Tests 63 passed (63).
  2. .NET host : compile BatcRemote.exe, avec l'app web à l'intérieur.
  3. Android (seulement si Android Studio est prêt) : copie l'app web dans le projet Android et compile l'APK. La première fois, cela télécharge les outils de compilation Android et peut prendre 10 minutes ou plus.

Quand tout s'est bien passé, les dernières lignes ressemblent à ceci :

OK -> C:\Dev\BATC-Remote\dist\BatcRemote-debug.apk (debug: no android\keystore.properties, not for distribution) OK -> C:\Dev\BATC-Remote\dist\BatcRemote.exe

Sans Android Studio, vous verrez (Android SDK not found … APK skipped) à la place de la première ligne : c'est normal, le programme Windows est compilé quand même.

Si le script s'arrête avec du texte rouge

Il s'arrête au premier problème. Lisez les dernières lignes en rouge et cherchez-les dans Dépannage. Une fois le problème réglé, relancez simplement la même commande.

Utiliser le résultat

Ouvrez le dossier du résultat :

explorer dist
  • BatcRemote.exe : un fichier unique, que vous pouvez copier où vous voulez. Double-cliquez dessus ; une icône apparaît près de l'horloge. La première fois, Windows demande l'accès au réseau : cochez Réseaux privés. Le README explique comment l'utiliser avec votre téléphone.
  • BatcRemote-debug.apk : copiez-le sur votre téléphone Android (câble USB, stockage en ligne…) et ouvrez-le sur le téléphone. Autorisez l'installation d'applications depuis cette source quand Android le demande.
L'app officielle est déjà sur votre téléphone ?

Android refuse d'installer une app par-dessus une autre signée avec une clé différente. Votre version et la version officielle sont signées avec des clés différentes : désinstallez l'une avant d'installer l'autre.

Facultatif : signer l'app Android

L'APK -debug convient parfaitement pour votre propre usage. Si vous voulez partager votre version avec d'autres personnes, signez-la avec votre propre clé. À faire une seule fois :

  1. Créez une clé, en dehors du dossier du projet (ici C:\Keys). L'outil demande un mot de passe et quelques informations ; votre nom ou votre pseudo suffit. 
    mkdir C:\Keys -Force
& "$env:ProgramFiles\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore C:\Keys\batc-remote-release.jks -alias batcremote -keyalg RSA -keysize 2048 -validity 10000
  2. Créez le fichier de réglages à partir de son modèle, puis ouvrez-le dans le Bloc-notes : 
    Copy-Item src\web\android\keystore.properties.example src\web\android\keystore.properties
notepad src\web\android\keystore.properties
    Dans le Bloc-notes, indiquez storeFile=C:/Keys/batc-remote-release.jks (avec des barres obliques /) et remplacez les deux change-me par votre mot de passe. Enregistrez et fermez.
  3. Relancez la compilation (étape 6). L'APK s'appelle maintenant dist\BatcRemote.apk, et le script affiche (signed).
Gardez votre clé en lieu sûr, et ne la partagez jamais
  • Faites une sauvegarde de C:\Keys\batc-remote-release.jks et de son mot de passe : chaque nouvelle version devra être signée avec la même clé, sinon les téléphones refuseront la mise à jour.
  • keystore.properties et la clé sont ignorés par Git : ils ne sont jamais envoyés sur GitHub.

Compiler une nouvelle version

Pour récupérer les dernières modifications et recompiler, ouvrez PowerShell et lancez :

cd C:\Dev\BATC-Remote
git pull
powershell -ExecutionPolicy Bypass -File .\build.ps1

Les compilations suivantes sont beaucoup plus rapides : les téléchargements restent sur votre PC.

Dépannage

Ce que vous voyezQue faire
git, node, npm ou dotnet « n'est pas reconnu en tant que nom d'applet de commande »Fermez PowerShell et ouvrez une nouvelle fenêtre. Si l'erreur persiste, l'outil n'est pas installé : réinstallez-le (étape 2), puis redémarrez le PC.
« winget n'est pas reconnu… »Installez Programme d'installation d'application (App Installer) depuis le Microsoft Store, ou passez par les sites officiels (étape 2, solution 2).
« Impossible de charger le fichier build.ps1, car l'exécution de scripts est désactivée sur ce système »Vous avez lancé .\build.ps1 directement. Utilisez la commande complète de l'étape 6, avec -ExecutionPolicy Bypass.
« Impossible de trouver le chemin d'accès … build.ps1 »PowerShell n'est pas dans le dossier du projet. Lancez d'abord cd C:\Dev\BATC-Remote.
Erreurs npm comme ETIMEDOUT, ECONNRESET ou EPERMVérifiez votre connexion Internet et relancez la compilation. EPERM signifie en général qu'un antivirus ou OneDrive bloque des fichiers : gardez le projet dans C:\Dev, en dehors de OneDrive.
Un test échoue (Tests … failed)Le code téléchargé est peut-être incomplet ou modifié. Retéléchargez-le (étape 5) dans un nouveau dossier vide.
Erreur NETSDK1045 (le SDK .NET actuel ne prend pas en charge .NET 8.0)Installez le SDK .NET 8 (étape 2), puis ouvrez une nouvelle fenêtre PowerShell.
« Android SDK not found … APK skipped »Normal si vous ne voulez pas l'app Android. Sinon, ouvrez Android Studio et faites l'étape 3.
« JAVA_HOME is not set » ou « No Java runtime »Android Studio est installé ailleurs. Indiquez son dossier Java pour cette fenêtre, puis relancez la compilation :
$env:JAVA_HOME = "D:\Chemin\Vers\Android Studio\jbr"
« You have not accepted the license agreements » (Android)Ouvrez Android Studio, puis Tools → SDK Manager, et installez les éléments proposés : il vous demandera d'accepter les licences. Relancez la compilation.
« Keystore file … not found » ou mot de passe incorrect (version signée)Vérifiez le chemin (avec des /) et les mots de passe dans src\web\android\keystore.properties. Pour revenir à l'APK de test, supprimez ce fichier.
Le téléphone n'arrive pas à ouvrir la page servie par BatcRemote.exeLa compilation n'y est pour rien : voir la partie Dépannage du README (même Wi-Fi, pare-feu Windows sur Réseaux privés).
