Build BATC Remote yourself

Before you start

Most people do not need this guide: ready-made files are available on the project's Releases page. Build BATC Remote yourself if you want to check exactly what you run, try the latest changes, or modify the app.

At the end of this guide you will have, in a folder called dist:

  • BatcRemote.exe, the small Windows program that serves the app to your phone;
  • BatcRemote-debug.apk, the Android app (only if you install Android Studio, see below).

What you need:

  • a PC with Windows 10 or 11 (64-bit);
  • an Internet connection (the tools and the first build download several hundred megabytes);
  • free disk space: about 2 GB for the Windows program only, and about 10 GB more for the Android app;
  • an account with the right to install software on the PC.
How to read this guide

Commands are shown in dark boxes. Click Copy, then paste them into PowerShell with a right-click (or Ctrl+V) and press Enter. Lines starting with # are comments: they are ignored.

Open PowerShell

PowerShell is the Windows window where you type commands. It is already installed.

  1. Click the Start button (or press the ⊞ Win key).
  2. Type PowerShell.
  3. Click Windows PowerShell (or Terminal). A window with a blinking cursor opens.

No need to run it as administrator: the installers will ask for permission themselves when needed.

Install the tools

BATC Remote is built with four free tools. The table tells you which ones you need.

ToolWhat it is forNeeded forSize
GitDownloads the source code from GitHub and keeps it up to dateRequired (or use the ZIP download in step 5)~ 350 MB
Node.js (LTS version, 22 or newer)Builds and tests the web app, the part you see on the phoneRequired~ 100 MB
.NET SDK 8Builds BatcRemote.exe (it also includes the runtimes needed to run it)Required~ 1 GB
Android StudioBuilds the Android app (it brings the Android SDK and Java)Android app only~ 3 GB + 3–6 GB of downloads

Option 1 (easiest): install with winget

winget is the installer built into Windows 10 and 11. Copy these commands into PowerShell. Each one downloads and installs a tool; accept the Windows prompts (“Do you want to allow this app to make changes?”) when they appear.

# Required
winget install -e --id Git.Git
winget install -e --id OpenJS.NodeJS.LTS
winget install -e --id Microsoft.DotNet.SDK.8

# Only if you want the Android app
winget install -e --id Google.AndroidStudio

The first time, winget may ask you to accept the terms of its sources: type Y and press Enter.

Option 2: install from the official websites

If winget is not available, download each installer and run it, keeping the default options:

  • Git: git-scm.com/download/win
  • Node.js: nodejs.org — choose the LTS version
  • .NET SDK 8: dotnet.microsoft.com/download/dotnet/8.0 — choose SDK, Windows x64
  • Android Studio: developer.android.com/studio
Important: close and reopen PowerShell

Once everything is installed, close the PowerShell window and open a new one (step 1). A window that was already open does not see the newly installed tools.

Set up Android Studio

Skip this step if you do not want the Android app. Android Studio must be opened once, so that it downloads the Android SDK.

  1. Open Android Studio from the Start menu.
  2. If it asks to import settings, choose Do not import settings.
  3. In the setup wizard, click Next, choose the Standard installation type, then Next.
  4. On the license screen, select each license on the left and click Accept, then Finish.
  5. Wait for the downloads to finish (this can take a while), then close Android Studio. You do not need to create or open a project.

Keep the default locations: the build script finds the Android SDK in %LOCALAPPDATA%\Android\Sdk and the Java runtime inside Android Studio's folder automatically.

Check the tools

In a new PowerShell window, run:

git --version
node --version
npm --version
dotnet --list-sdks

You should see something like this (your numbers may be higher):

git version 2.51.0.windows.1 v24.19.0 11.6.0 8.0.425 [C:\Program Files\dotnet\sdk]
  • node must show v22 or higher.
  • dotnet --list-sdks must list at least one SDK starting with 8. or higher.

If one of them answers “is not recognized as the name of a cmdlet”, see Troubleshooting.

Download the source code

We will put the code in C:\Dev\BATC-Remote. A short path without spaces avoids problems, and it is best to stay out of folders synchronised by OneDrive.

mkdir C:\Dev -Force
cd C:\Dev
git clone https://github.com/Proxi64/BATC-Remote.git
cd BATC-Remote

The last command moves PowerShell into the project folder. The prompt now ends with C:\Dev\BATC-Remote>.

Without Git

On the GitHub page, click the green Code button, then Download ZIP. Extract the ZIP into C:\Dev and rename the extracted folder to BATC-Remote. Then, in PowerShell: cd C:\Dev\BATC-Remote. You will not be able to use git pull later (step 9): download the ZIP again instead.

Build

Everything is done by one script, build.ps1, at the root of the project. Run it from the project folder:

powershell -ExecutionPolicy Bypass -File .\build.ps1

-ExecutionPolicy Bypass lets Windows run this script once, without changing any security setting on your PC.

The script runs these stages one after the other; the coloured titles show where it is:

  1. Web app: downloads the libraries it needs, checks the code, runs the 63 automated tests, then builds the app. You should see Tests 63 passed (63).
  2. .NET host: builds BatcRemote.exe, with the web app inside it.
  3. Android (only if Android Studio is set up): copies the web app into the Android project and builds the APK. The first time, this downloads the Android build tools and can take 10 minutes or more.

When everything went well, the last lines look like this:

OK -> C:\Dev\BATC-Remote\dist\BatcRemote-debug.apk (debug: no android\keystore.properties, not for distribution) OK -> C:\Dev\BATC-Remote\dist\BatcRemote.exe

Without Android Studio, you will see (Android SDK not found … APK skipped) instead of the first line: this is normal, the Windows program is built anyway.

If the script stops with red text

It stops at the first problem. Read the last red lines, and look for them in Troubleshooting. Once fixed, simply run the same command again.

Use what you built

Open the result folder:

explorer dist
  • BatcRemote.exe: a single file that you can copy anywhere. Double-click it; an icon appears near the clock. The first time, Windows asks about network access: tick Private networks. The README explains how to use it with your phone.
  • BatcRemote-debug.apk: copy it to your Android phone (USB cable, cloud drive…) and open it on the phone. Allow installing apps from this source when Android asks.
Already have the official app on your phone?

Android refuses to install an app over another one signed with a different key. Your build and the official release are signed with different keys: uninstall one before installing the other.

Optional: sign the Android app

The -debug APK is perfect for your own use. If you want to share your build with others, sign it with your own key. Do this once:

  1. Create a key, outside the project folder (here C:\Keys). The tool asks for a password and a few details; your name or nickname is enough. 
    mkdir C:\Keys -Force
& "$env:ProgramFiles\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore C:\Keys\batc-remote-release.jks -alias batcremote -keyalg RSA -keysize 2048 -validity 10000
  2. Create the settings file from its template, then open it in Notepad: 
    Copy-Item src\web\android\keystore.properties.example src\web\android\keystore.properties
notepad src\web\android\keystore.properties
    In Notepad, set storeFile=C:/Keys/batc-remote-release.jks (with forward slashes) and replace both change-me with your password. Save and close.
  3. Run the build again (step 6). The APK is now dist\BatcRemote.apk, marked (signed).
Keep your key safe, and never share it
  • Make a backup of C:\Keys\batc-remote-release.jks and its password: every future version must be signed with the same key, otherwise phones refuse the update.
  • keystore.properties and the key are ignored by Git: they are never sent to GitHub.

Build a newer version later

To get the latest changes and build again, open PowerShell and run:

cd C:\Dev\BATC-Remote
git pull
powershell -ExecutionPolicy Bypass -File .\build.ps1

The next builds are much faster: the downloads are kept on your PC.

Troubleshooting

What you seeWhat to do
'git', 'node', 'npm' or 'dotnet' “is not recognized as the name of a cmdlet”Close PowerShell and open a new window. If it still fails, the tool is not installed: install it again (step 2), then restart the PC.
“winget is not recognized”Install App Installer from the Microsoft Store, or use the official websites (step 2, option 2).
“build.ps1 cannot be loaded because running scripts is disabled on this system”You ran .\build.ps1 directly. Use the full command of step 6, with -ExecutionPolicy Bypass.
“Cannot find path … build.ps1”PowerShell is not in the project folder. Run cd C:\Dev\BATC-Remote first.
npm errors such as ETIMEDOUT, ECONNRESET or EPERMCheck your Internet connection and run the build again. EPERM usually means an antivirus or OneDrive is locking files: keep the project in C:\Dev, outside OneDrive.
A test fails (Tests … failed)The downloaded code may be incomplete or modified. Download it again (step 5) in a new, empty folder.
NETSDK1045 “The current .NET SDK does not support targeting .NET 8.0”Install the .NET SDK 8 (step 2), then open a new PowerShell window.
“Android SDK not found … APK skipped”Normal if you do not want the Android app. Otherwise, open Android Studio and complete step 3.
“JAVA_HOME is not set” or “No Java runtime”Android Studio was installed somewhere else. Point the build to its Java folder for this window, then run the build again:
$env:JAVA_HOME = "D:\Path\To\Android Studio\jbr"
“You have not accepted the license agreements” (Android)Open Android Studio, then Tools → SDK Manager, and install the suggested items: this asks you to accept the licenses. Run the build again.
“Keystore file … not found” or “wrong password” (signed build)Check the path (with /) and the passwords in src\web\android\keystore.properties. To go back to the debug APK, delete that file.
The phone cannot open the page served by BatcRemote.exeThe build is fine: see the troubleshooting part of the README (same Wi-Fi, Windows Firewall on Private networks).
